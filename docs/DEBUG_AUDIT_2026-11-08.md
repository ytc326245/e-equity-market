# 0.3.1 调试与数据核对记录

本次检查基于 0.3.0 源码，修复发布为 0.3.1，手机版为 1.1.1。使用 Chromium 调试协议记录界面异常及网络结果，测试账户独立于实际账户；没有读取或重置用户的本金、持仓和交易记录。

## 核对范围与证据

- 检查本地 13,129 条目录记录的结构、代码及重复项，未发现无效或重复记录。这不等于逐一核验全市场报价。
- 对全部 22 个内置常用标的读取本程序、Yahoo Finance 与 TradingView 的实际接口，核对价格、涨跌、昨收、成交量、PE、EPS、市值、最近季度 PB、股息率、52 周区间及 ETF 资料。未提供的字段单独记录，不填零。
- AAPL、MSFT、SPY 各核对 390 个正常时段分时点，并与两个平台的一分钟价格作同时间比较；也检查 1 月、3 月、1 年历史图。
- 使用合成行情在 Windows/手机界面各执行 16 项操作检查，包括买卖、部分卖出、超额下单、读取失败、恢复、重载和指标弹窗；未发现未处理的界面异常或应用控制台错误。手机买卖请求仅发送证券代码。
- 公开测试使用合成数据；本次原始市场响应、完整对照表、调试日志及账户位于被忽略的工作目录，不随源码发布。

参考页面：[Yahoo AAPL](https://finance.yahoo.com/quote/AAPL/)、[TradingView AAPL](https://www.tradingview.com/symbols/NASDAQ-AAPL/)、[TradingView 财务期间说明](https://www.tradingview.com/support/solutions/43000543506-how-to-access-financial-data-on-tradingview/)、[NYSE 交易日历](https://www.nyse.com/trade/hours-calendars)。

## 已修复的可复现场景

| 问题 | 具体原因 | 修复 |
| --- | --- | --- |
| QQQ 年费率旧值 | 只读取汇总/普通统计字段，遗漏 `fundProfile.feesExpensesInvestment.annualReportExpenseRatio`，落到 Nasdaq 旧汇总值 | 读取基金资料。无法核验更新时间的汇总费率显示缺失，保留来源解释 |
| 中概股 EPS 被隐藏 | 把损益表的 `financialCurrency` 当成报价单位 EPS 的币种，错误排除 ADR 数据 | 按 `price.currency` 与上市证券/存托凭证单位显示，并标明原财报币种 |
| BRK.B 等类别股缺指标 | Yahoo 使用连字符代码，目录使用点号 | 映射到 Yahoo 对应代码，并核验返回标的 |
| 新 HTTP 响应仍可包含旧交易日报价 | 仅检查软件读取时间 | 来源日期已知时，必须与当前纽约日期一致才可成交 |
| 来源返回其他标的仍可能被贴上请求代码 | 行情适配器未检查响应里的证券代码 | 在使用报价前拒绝不匹配响应 |
| 历史图出现平价占位记录 | 日线直接采用 close，未识别全平 OHLC 且成交量缺失/为零的占位行 | 排除该类不可核验记录，标注日期缺口；真实剧烈波动与有成交量的平价记录不按幅度删除 |
| 半美分价格及精细费率被截成两位 | 单价与现金金额共用格式化函数 | 单价最多六位小数，现金金额仍为美分；基金百分比费率最多四位小数 |
| 迟到报价覆盖新请求 | 报价缺少请求版本保护 | 新请求生效后，丢弃旧请求的成功或失败结果 |
| 缺失涨跌幅显示为零 | 空值使用零作为默认值 | 保留缺失标记 |
| 不完整财务数据恢复慢 | 界面统一等待五分钟后重读 | 不完整结果 30 秒后可重试，完整结果保留五分钟缓存 |

这些新增回归场景在未修复的 0.3.0 中出现 10 个失败，修复后通过。另执行 1,500 轮随机小数股买卖尝试，检查现金、成本、已实现盈亏的精确守恒及备份重放。

QQQ 当前费率与 [Invesco 官方资料](https://www.invesco.com/qqq-etf/en/home.html) 的 0.18% 一致；SPY 精细费率与 [State Street 官方资料](https://www.ssga.com/us/en/institutional/etfs/state-street-spdr-sp-500-etf-trust-spy) 的 0.0945% 一致。

## 跨平台仍可能不同的字段

- 22 个标的的 52 周区间在一美分以内相符。最近成交价格中 14 个与 Yahoo 完全一致，另外 8 个有小幅差异；主界面现明确说明是来源最近成交价，不能把不同来源的最后成交记录都视作统一的官方收盘值。
- PE/EPS 可能有小数精度、财报更新及调整口径差异。PB 必须使用最近季度字段比较：TradingView 的 `price_book_fq` 与 `price_book_ratio` 不能混作同一个期间；美股样本中的明显 PB 差异因此得到解释。ADR 的股本、汇率和财报口径仍需按具体来源核对，不把上游差异强行改成一致。
- 来源成交量存在覆盖与修订差异。缺少逐笔成交明细时，不能仅靠两个总数确定哪一个是最终全市场总量。
- ETF 资产资料的基准日期常缺失，部分基金的基金总资产包括多类份额。界面已改为“基金资产（来源口径）”，不再暗示是当前 ETF 单一份额的实时规模。[Vanguard 官方 VOO 资料](https://fund-docs.vanguard.com/F0968.pdf) 明确区分 ETF 总资产与基金总资产。
- 日线共作 2,059 次同日价格比较，2,058 次在 1.1 美分以内；AAPL 的 2026-04-29 有一处与 TradingView 相差 0.05 美元，而 Nasdaq 与 Yahoo 一致。该差异保留记录，不据此随意更改价格。
- SPY 2026-04-20 的 Nasdaq 日线为无成交量平价占位，沿用前一交易日值；两个对照平台提供一致的实际日线。程序选择留空并说明，不静默拼接其他来源。
- 分时采样与一分钟 OHLC 收盘不是同一种数据。三个样本与两平台的同时间走势相关系数均超过 0.999，最大同分钟差异约 0.31 美元；不能据此声称每一笔成交或开收盘竞价均已核验。

这是一轮有明确覆盖范围的审计，不承诺所有证券、所有时段和所有上游数据永久无误。分红、拆股、手续费、滑点等仍属于当前模拟模型尚未实现的功能。
